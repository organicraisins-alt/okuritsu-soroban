# 億率の運用手順

最終更新：2026-10-28。公開サイト：https://okuritsu-soroban.com/ 。変更は検証と運営者の承認後に公開する。

## 毎月のSearch Console確認

1. 月初に過去28日とその前の28日を比較し、検索パフォーマンスの表示回数・クリック数・CTR・平均掲載順位をページと検索語ごとに保存する。季節記事は前年同時期とも比較する。
2. 表示が多くCTRが低い記事は、検索語とtitle・description・冒頭の結論が一致するか確認する。金額、利益と売上、適用年、主な前提を明確にし、誇大な効果を書かない。一度に複数の変更を重ねず、変更日を記録して数週間後に比較する。
3. 順位や表示が落ちた記事は、索引状況、canonical、サイトマップ、リンク切れ、古い年度や出典、検索意図とのずれを確認する。税額を増減させるための文章変更や薄いページの量産をしない。
4. 収録レポートや構造化データの問題を調べる。公開直後・更新直後は反映待ちと不具合を区別する。FAQPage等が正しくても検索での特別な表示を保証されるわけではない。

## 税制改正と料率改定

1. 国税庁、厚生労働省、日本年金機構、協会けんぽ、自治体の公式資料を確認する。大綱・法案と成立済み法令、施行日、所得税の年分と保険料の年度を区別する。
2. src/lib/tax/params.tsを更新する。根拠URL、対象年・適用期間・確認日を記録し、sources.tsの出典・確度も見直す。未確認値を推測で確定しない。
3. 独立した検算から新しい回帰期待値を確認し、regression-cases.tsを更新する。旧プロトタイプの期待値とパラメータを上書きしない。logicは同じ値を自動表示するが、計算手順・端数・制約の本文も確認する。
4. npm test → npm run check → PUBLIC_SITE_URL=https://okuritsu-soroban.com ASTRO_TELEMETRY_DISABLED=1 npm run build。新旧の6ケース、控除境界、保険料上限、億率のseed固定テストを確認する。
5. 全ページ・OG画像を再生成し、375px表示、記事の年分・更新日、内部リンク、sitemap、canonicalを確認する。所得と保険料の実請求の差を消さない。
6. 承認後のみnpm run deployで公開する。公開後に代表ページ・robots・サイトマップ・HTTPSを確認する。wwwの301は運営者からカスタムドメイン追加の連絡後に確認する。変更履歴とデプロイURLを残す。

## GA4と共有の扱い

PUBLIC_GA_IDがあるビルドだけGA4を読み込む。現在は未設定。イベントはokuritsu_calculateとshare_click。固定のpage_type分類のみを付け、イベントのpage_locationは同一オリジンのルートURL、page_referrerは空にする。金額・億率・年齢・資産・生活費・掛金・seed・入力URL・Xリンクをイベントに含めない。通常のpage_viewもクエリ・fragmentを除いて送る。

**有効化前にGA4管理画面で拡張計測のフォーム操作・離脱クリック・ブラウザー履歴によるページビューを無効にする。** 自動計測が共有リンクや入力条件を収集しない設定を確認する。これはブラウザー側のカスタムイベント実装だけでは制御できない管理画面側の作業である。

今回指定の共有URLはquery形式。再読み込み・共有先でのページ取得では入力条件が配信サーバーへ届く。X共有は投稿画面を開いた時点で本文とURLがXへ渡る。計算APIやデータベースへの送信・保存は行わないが、「入力は外部に一切出ない」と書かない。privacyの説明と実装を一緒に更新する。

## 公開前に運営者が記入・確認する項目

- /about/ の活動名・経歴は運営者の確認済み文章で公開済み。連絡先は窓口準備まで項目ごと非表示。経歴を推測で追加しない。
- 監修者は未定で欄を非表示。決まるまで監修済みと表示しない。
- /contact/ の窓口は準備中（今回の指示で当面は用意しない）。準備できたら受付方法と、非表示の連絡先を更新する。
- 広告枠は準備中。採用する提携先の正式URL・PR表示・条件を確認する。金融商品を特定して推奨する文面を足さない。
- www.okuritsu-soroban.comは最終確認時DNS未設定。運営者がPagesのカスタムドメインとして追加した連絡を受け、証明書が有効になってから、同梱_redirectsによる301を実測する。今回はDNSや公開設定を変更していない。
- OG画像は静的な既定例。共有した個別入力に応じて画像が変わるとは表示しない。
- 次回公開前に税制・各制度の要確認項目と、iDeCoの適用時期を再確認する。

## 2026-10-28の検索流入改善

- 変更前記録：`docs/search-console/2026-10-28-baseline.md`。利用者の画面が未着の場合は準備中とし、数値を0で埋めない。公開は記録後。
- 変更日・対象ページを記録し、Search Consoleのデータがそろったら過去28日とその前の28日を比較する。公開直後は比較期間が足りないことを明記し、直後の増減を施策の効果と断定しない。
- パフォーマンスは検索タイプ・国・端末・期間の条件をそろえる。検索語を「手取り」「会社員比較」「法人化」「インボイス」「独立準備」へ分類し、表示はあるがクリックされないページと、そもそも表示されないページを分ける。
- インデックス登録は登録済み・未登録・理由・最終更新を記録する。サイトマップで検出した60URLは登録済み件数ではない。6件の雛形を除外する方針は維持する。

- 新規記事は、Search Consoleに出た疑問と既存ページの不足を確認して選ぶ。記事の量産や変更のない日付更新は行わない。
