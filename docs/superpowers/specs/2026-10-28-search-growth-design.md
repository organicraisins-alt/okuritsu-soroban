# 検索流入改善・第1回の提案

調査日：2026-10-28。実装承認前の提案。アプリケーションの変更・公開は未実施。

## 目的と判断材料

フリーランス・独立予定者が、検索した疑問に答えを得て、自分の条件で計算できる入口を整える。検索順位や流入増加は保証せず、公開後のSearch Consoleの表示回数・クリック数・CTR・検索語別の推移で判断する。

既存のSearch Console登録記録はサイトマップの検出60ページ。検出数をインデックス登録数とは扱わない。今回、Search Consoleの最新実績値は取得していない。キーワードの検索数・競合順位も未測定。

## 調査からの方針

- Googleは利用者の役に立つ独自情報・明確な根拠を重視する。計算ライブラリに基づく条件比較を強みにする。文字数やページ数そのものを目的にしない。
- titleはページ内容を具体的・簡潔に表す。文字数32文字などを順位の条件とは扱わない。
- 関連リンクはそのページの疑問を解決する先へ、具体的な文言で付ける。
- 内容を確認せず更新日だけ新しくしない。確認日・内容更新日・公開日は区別する。
- FAQの本文は利用者向けに残す。Google公式の更新履歴ではFAQリッチリザルトは2026-05-07から終了しており、検索表示の拡張を目的に工数を使わない。

## 現在のコードで確認できた改善点

1. `src/data/related.ts` は多くのページで利益800万円・エンジニア・独立1年目の同じ組合せになる。住民税の記事なら支払いカレンダー、国保の記事なら任意継続比較など、話題に合わせて変える。
2. `GuidePage.astro` のArticle公開日・更新日は全記事で2026-10-27固定。見える出典欄は2026-10-26で食い違う。記事データに日付を持たせる。履歴・公式資料を確認できない日付は創作しない。
3. ガイド下部の長い共通説明・リンクが記事の話題と一致しない。必要な前提を短くまとめ、詳細は開閉して読めるようにする。
4. `/tools/invoice/` のtitleは「インボイス計算」のみ。登録比較・消費税の試算ができることを具体的に示す。ほかの主要ページもtitle・見出し・説明の整合を確認する。
5. BaseLayoutにfavicon指定がなくpublicにも専用アイコンがない。「億率」の既存意匠に沿ったSVGアイコンを用意する。検索結果への表示は保証しない。
6. `docs/operations.md` には公開済みにもかかわらずローカルのみと書かれた箇所がある。実態に合わせる。

既存のcanonical・サイトマップ・出典ページ・運営者情報・年収別計算結果は活用する。既存URL、税計算の前提、承認済みの運営者の経歴、入力金額の取り扱いは維持する。

## GitHub OSSの比較・選定

候補：GoogleChrome/lighthouse と withastro/astro。

参照先は https://github.com/GoogleChrome/lighthouse を選ぶ。Webページの表示性能・アクセシビリティ・基本的なSEOの問題を、開発者が再現可能な条件で確認する課題を解くOSS。Node.jsとChromeを使い、Apache-2.0。公式のリリースページに継続した公開履歴がある（https://github.com/GoogleChrome/lighthouse/releases）。保守状況は安全性の保証ではないため、今回は追加導入・依存更新は行わない。

再利用するのは「条件を固定して確認し、結果を保存する」という設計。点数を検索順位や利用者数の予測へ読み替えない。ブラウザの計測にはアクセス先への通信が伴うため、認証情報や利用者の入力を計測データへ入れない。ユーザーが既に省略を認めた追加Lighthouse計測は本作業の必須にはしない。

Astroは記事・ツールの静的HTMLを届ける現在の構成に適合しており、そのまま使う。別フレームワークへの移行やSEOサービスの追加は不要。

## 技術選定・構成

Astro / TypeScript / 既存CSS / Vitest / Cloudflare Pagesを継続。新規ランタイム依存なし。検索用文章・記事ごとの関連リンク・記事日付を型付きデータで管理し、既存コンポーネントから静的HTMLへ出力する。金額は必ず `src/lib/tax` を利用する。GA4はPUBLIC_GA_IDが設定された場合のみ読み込み、金額をイベントに含めない。
